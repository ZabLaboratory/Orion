# Orion static size-lowering performance evidence

## Scope and hypothesis

Work unit: local-20260927-orion-split-size

Candidate branch: eleven/local-20260927-orion-split-size

Comparison base: PR #453 head 574dd4d2d73069933b1726b241b7fb3172ef989c

The compiler repeatedly decoded each nested size object into a temporary
map[string]json.RawMessage, although lowering consumes only the exact keys
"w" and "h". The candidate adds a bounded scanner for valid, unescaped JSON
objects and clones only the selected raw values. Escaped or malformed input
continues through the existing encoding/json path. This is shared compiler
behavior; it adds no product-specific branch and touches no Pulsar code.

Parity coverage includes nested unrelated values, duplicate dimensions,
case-sensitive names, escaped names and values, non-object JSON, malformed
members, trailing data, and independent ownership of the returned RawMessages.

## Focused A/B benchmark

Machine: Windows/amd64, AMD Ryzen 7 3800X. Fixture:
BenchmarkCompileStaticLSMLRepresentative, the same representative 250-text-node
LSML compile on both revisions.

Command on each revision:

    go test ./internal/compiler -run '^$' -bench '^BenchmarkCompileStaticLSMLRepresentative$' -benchmem -count=10

The final-source A/B medians were:

| Revision | Median time | Median B/op | Median allocs/op |
| --- | ---: | ---: | ---: |
| Base 574dd4d | 3.842 ms | 1,094,679 | 13,345 |
| Candidate | 3.503 ms | 942,753 | 11,337 |

This is an 8.8% lower median compile time, 13.9% fewer allocated bytes, and
2,008 fewer allocations per operation (15.1%). A second final-source run using
benchtime=2s and count=5 confirmed the direction: 3.899 ms → 3.500 ms
(-10.2%), 1,094,034 → 941,425 B/op (-13.9%), and 13,345 → 11,337 allocs/op.

These are local microbenchmark results, not production latency claims.

## Allocation profile

The same benchmark's baseline pprof attributed 313.07 MB cumulative allocations
to splitSize across 1,718 iterations. The final candidate profile attributed
47.52 MB across 1,846 iterations. Normalized per iteration, splitSize's
cumulative allocations fall by approximately 86%. The remaining allocations
are principally the owned copies of width and height values.
