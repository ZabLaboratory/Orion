# Orion `NewScene` initialization optimization

## Scope

Follow-up experiment to, and intentionally separate from, Orion PR #451
(`48aa751cfe5ef795700c6ed997563d5e762e4182`). No Pulsar files or contracts are
changed. The compiler candidate and baseline were the same commit and produced
the same 20,001-node scene version:

`sha256:119011db23be0a489d006bd5bf8c7cbfbca3f14356b639bd05fac36558675401`

The runtime candidate changes only `NewScene` construction:

- preallocate `computeOrder` to the exact node count;
- size the reverse-adjacency `consumers` map from incoming edges on non-input
  nodes, capped at the node count, so input-only scenes reserve no empty table;
- keep named `Inputs` authoritative through indexed access instead of copying
  every `Input.From` into a per-node `[]string`; legacy `Upstream` remains the
  fallback;
- deduplicate up to eight upstream paths with a bounded stack array rather than
  allocating a per-node map;
- retain the map-based deduplication path above eight inputs.

## Focused A/B measurement

Command, run on both revisions with the same build and benchmark settings:

```text
go test ./internal/runtime -run '^$' -bench '^BenchmarkNewScene20kColdStart$' -benchmem -benchtime=750ms -count=5
```

Machine: Windows/amd64, AMD Ryzen 7 3800X. Each benchmark compiles the fixture
before starting the timer; timed work is runtime `NewScene` loading and full
cold evaluation. Five individual observations on the dense 20,001-node fixture:

| Revision | NewScene ms/op | Median B/op | Median allocs/op |
| --- | --- | ---: | ---: |
| Baseline | 45.5612, 43.5584, 49.3292, 48.4838, 46.2544 | 40,443,944 | 200,294 |
| Candidate | 37.0711, 41.2024, 39.7351, 41.2969, 41.7023 | 26,462,125 | 180,212 |

Median `NewScene` time improves from 46.2544 ms to 39.7351 ms (−14.1%). Median
allocated bytes improve from 40,443,944 B/op to 26,462,125 B/op (−34.6%). The
allocation count falls by 20,082/op (200,294 to 180,212).

Sparse-shape command:

```text
go test ./internal/runtime -run '^$' -bench '^BenchmarkNewScene20kInputOnly$' -benchmem -benchtime=750ms -count=5
```

This graph has 20,000 input nodes and no edges. `NewScene` times were 7.0157,
8.4212, 9.0635, 8.3906, and 11.5870 ms/op at baseline versus 2.8825, 2.8341,
2.9694, 2.8356, and 2.8070 ms/op on the candidate: median 8.4212 ms to 2.8341
ms (−66.4%). Median allocation bytes fell from 16,570,169 to 4,794,755 B/op
(−71.1%), and allocations from 182 to 159/op. The candidate map capacity is
zero for this no-edge graph.
