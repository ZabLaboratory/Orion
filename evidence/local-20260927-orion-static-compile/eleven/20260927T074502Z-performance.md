# Orion static text-style lowering performance evidence

## Scope and hypothesis

Work unit: `local-20260927-orion-static-compile`

Branch: `eleven/local-20260927-orion-static-compile`

Final base under test: merged Orion `origin/main` at
`f048cc973f9789ec4db8b0676e1293a57472d02e` (PR #452).

Control revision: `7099201b6ceaa1c85b9ec48a1953c34dc1e68bd0` (PR #451).

This is a generic compiler-path optimization. It changes neither product-specific
behavior nor Pulsar files/contracts. `lowerText` formerly decoded every nested
text `style` object into `map[string]json.RawMessage`, although only keys in the
shared `textRenames` table survive lowering. The common unescaped object form now
uses a bounded scan without allocating a temporary style map and clones only
mapped values. Escaped JSON and unsupported/malformed input continue through the established
`encoding/json` compatibility path.

The initial allocation profile supported this target: in a three-second run,
`lowerText` accounted for 364.09 MB cumulative allocations, including 157.03 MB
from unmarshalling nested style maps. The sample covered 730 benchmark
iterations. Profile files were kept in the machine temp directory, not committed.

## Focused A/B benchmark

Command on both revisions:

```text
go test ./internal/compiler -run '^$' -bench '^BenchmarkCompileStaticLSMLRepresentative$' -benchmem -count=5
```

Machine: Windows/amd64, AMD Ryzen 7 3800X. The benchmark compiles the same
representative 250-text-node LSML fixture; the baseline and candidate compiler
sources were both based on PR #451, so PR #452's independent runtime changes do
not enter this A/B measurement.

| Revision | Time ms/op (5 runs) | Median B/op | Median allocs/op |
| --- | --- | ---: | ---: |
| Baseline | 4.518091, 4.490829, 4.197817, 4.170256, 4.089531 | 1,293,920 | 17,348 |
| Candidate | 3.526272, 3.548886, 3.447994, 3.470257, 3.456552 | 1,095,007 | 13,345 |

Median compilation time falls from 4.197817 ms to 3.470257 ms (−17.3%). Median
allocated bytes fall by 198,913 B/op (−15.4%); allocations fall by 4,003/op
(−23.1%). These are local benchmark results, not a production latency claim.

## Limits

NewScene execution, frame rendering, network latency, or image decode time. The
post-merge browser rerun for this compiler change remains required after its PR
is merged.
